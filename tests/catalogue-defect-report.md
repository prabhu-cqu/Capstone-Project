# SmartShop AI – Product Catalogue Defect Report

## 1. Purpose

This document defines the defect reporting process for the SmartShop AI Product Catalogue testing increment.

Defects identified during execution of FR1, FR2 and FR3 test cases will be recorded here and linked to the relevant test case.

## 2. Defect Status

The following statuses will be used:

- Open – Defect has been identified and recorded.
- In Progress – A team member is investigating or fixing the defect.
- Ready for Retest – A fix has been completed and requires verification.
- Closed – The fix has been successfully retested.
- Reopened – The defect still exists after retesting.

## 3. Severity Levels

| Severity | Description |
|---|---|
| Critical | Prevents major application functionality from operating |
| High | Major feature does not work correctly |
| Medium | Feature works but has a significant issue |
| Low | Minor issue that does not prevent normal use |

## 5. Defect Record Template

### DEF-XXX – Defect Title

**Related Test Case:** TC-CAT-XXX

**Requirement:** FR1 / FR2 / FR3

**Date Identified:** Not recorded

**Severity:** Critical / High / Medium / Low

**Status:** Open

**Description:**  
Describe the problem identified during test execution.

**Steps to Reproduce:**
1. Open SmartShop AI.
2. Navigate to the relevant Product Catalogue function.
3. Perform the actions defined in the related test case.
4. Observe the result.

**Expected Result:**  
Record the expected behaviour from the related test case.

**Actual Result:**  
Record what actually occurred during testing.

**Evidence:**  
Add a screenshot, error message or other supporting evidence.

**Assigned To:**  
To be assigned.

**Fix/Commit Reference:**  
To be added after the defect is fixed.

**Retest Result:**  
Not retested.

## 6. Retesting Process

When a reported defect is fixed:

1. Confirm that the relevant fix is available.
2. Execute the original test case again.
3. Compare the actual result with the expected result.
4. Record the retest result.
5. Mark the defect as Closed if the test passes.
6. Reopen the defect if the problem remains.

No defects are recorded as actual project defects until they are identified during execution of the Product Catalogue test cases.
